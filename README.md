## 网页版全屏（仅 GitHub Pages）

根目录的 `index.html` 额外加载了 `src/ui/fullscreen.js`，提供**强制全屏**：

- 战斗信息栏右上角有「全屏 / 退出全屏」按钮（**取代了原来的「自动」按钮**）
- 按钮在舞台内部，所以竖屏旋转时会跟着画面一起转，方向永远和界面一致
- 首次点击或触摸页面时自动尝试进入全屏（浏览器要求必须有用户手势）
- 退出后不会自动重进；想彻底关掉自动全屏，网址加 `?fs=0`
- iOS Safari 不支持元素全屏，按钮会自动隐藏，改为提示「分享 → 添加到主屏幕」
- 自动战斗仍可用网址参数开启：`?auto=1`

> **小工具版本（`dist/`）不加载这个脚本**，打包给小工具时完全不受影响。

## 屏幕比例与横竖屏（重要）

游戏画面是**固定 2:1 比例**（与参考图一致），整块画面等比缩放到窗口里，
剩下的地方**全部用黑色填充**（黑边留白），所以手机上横屏时比例和桌面上完全一致。

- 设计分辨率：**840 × 420**
- 版式：左 20% | 中 60% | 右 20%
- 中列竖向：上 48.5% = 战斗信息栏，下 = 三张卡牌
- 缩放：`src/main.js` 的 `DESIGN_W / DESIGN_H` + `fitStage()`（`transform: rotate + scale`）
- 改设计分辨率：同时改 `main.js` 的 `DESIGN_W/DESIGN_H` 和 `styles/pixel.css` 里 `.stage` 的 `--w/--h`

### 竖屏自动旋转

- **横屏**（宽 > 高）：正常渲染，按 2:1 居中，多余留黑
- **竖屏**（高 > 宽）：把整个 840×420 画面 **顺时针旋转 90° 铺满屏幕**，玩家把手机横过来就是正的
  —— 这样竖屏下也不会只剩中间一小条
- 首次进入竖屏会闪一条「↻ 把手机横过来玩」的提示（2.4 秒后淡出）
- 想换成逆时针（左撇子 / 习惯反方向），把 `main.js` 里的 `rotate(90deg)` 改成 `rotate(-90deg)`

> 旋转是靠 CSS `transform` 做的，点击/触摸坐标会跟着一起转，不需要额外换算。
> 飘字层与结算弹窗都放在 `.stage` 内部，所以会跟着画面一起旋转。

## 已实现的对战规则

| 项目 | 规则 |
| --- | --- |
| 出招顺序 | 我1 → 敌1 → 我2 → 敌2 → 我3 → 敌3，循环往复；阵亡角色自动跳过 |
| 角色属性 | 每个角色 **3 个元素**（主 + 2 副），主元素决定被什么克制 |
| 技能来源 | 三个元素各对应 1 张技能卡，卡牌区永远显示"当前回合角色"的 3 张卡 |
| 技能类型 | `攻击` 只能对敌方释放；`增益` 对己方=强化，对敌方=攻击 |
| 操作 | 点卡牌 → 点目标（只有一个目标时自动释放）；再点同一张卡 / `Esc` 取消；键盘 `1/2/3` 选卡 |
| 元素克制 | 技能元素打目标主元素：有力 ×1.5，无力 ×0.5，其余 ×1.0 |
| 状态 | 增益：攻↑ 防↑ 暴↑ 回春 护盾；减益：中毒 灼烧 易伤 虚弱 破防 攻↓ 麻痹 |
| 伤害 | `威力 × 攻击/100 × 100÷(100+防御) × 元素克制`，再乘增伤/减伤，暴击 ×1.6，±6% 浮动 |

## 单个状态栏的结构

```
┌──────┬──────────────────┬──────┐
│ 元素 │                  │ buff │
│ 图标 │     角色头像      │ debuff│
│ 图标 │                  │  ↓   │
│ 图标 │                  │ 依次 │
├──────┼──────────────────┤ 往下 │
│ 等级 │    血条 + 数值     │  排  │
└──────┴──────────────────┴──────┘
```

- 左侧金色竖条被横线分成**上半段（长条）**和**下半段（方块）**：
  - 上半段：**三个元素徽章**（主元素 + 2 副元素）等大、居中排列
  - 下半段：**粗体等级数字**
- 中间：头像（底部是名字条）→ 血条
- 右侧金色竖条：buff / debuff **从上往下**排，先占上侧，之后新状态接在下面、水平居中
- 鼠标悬停徽章/头像可以看到属性、克制关系、攻防数值


## 伤害怎么算

技能本身**没有威力数值**，伤害只跟角色攻击力有关（对应「数值对照表.txt」的 attack）：

```
伤害 = 攻击力 × 技能倍率 × 元素倍率 × (1+增伤) × (1+易伤) × 暴击 × 随机(0.94~1.06)
```

- **技能倍率**：绝大多数是 100% 攻击力；表里写明百分比的按表（如灼烧之炭 85%、感染扩散 80%）
- **元素倍率**：技能元素 打 目标主元素 → 有力 ×1.5 / 无力 ×0.5 / 其它 ×1
- **不再计算防御**（数值表里没有防御栏）
- 暴击 1.6 倍，基础暴击率 10%
- 第 11 回合起「白热化」：每回合全场伤害 +18%，第 40 回合仍未结束则按剩余总生命判定

伤害数字用「亿 / 万」缩写显示（例：`77.9亿`），血条**只显示长度、不显示数字**。

### 辅助技能也可以打敌人

所有「对友方」的技能都有两种用法：

| 点击目标 | 结果 |
| --- | --- |
| 我方角色 | 正常结算辅助效果 |
| 敌方角色 | 就是上面那条统一规则——只打一次 100% 攻击，**没有任何附加效果** |

- 选卡后友方和敌方都会亮起：友方标「强 化」，敌方标「有力 ×1.5 / 无力 ×0.5」
- 日志会标「（普通攻击）」
- AI 也这么用：辅助收益不如一刀时直接把辅助牌当攻击打
- 对手龙「60% 不出防御牌」时，防御牌仍可以当普通攻击使用

### 对手龙规则（平衡设定）

敌方三条龙统一遵守这三条，配置在 `src/engine/battle.js` 的 `ENEMY_RULES`：

| 规则 | 值 | 说明 |
| --- | --- | --- |
| `startFullHp` | 固定生效 | 每局开局 100% 生命，不继承上一局损耗 |
| `missChance` | 0.2 | 打出的攻击有 **20% 概率落空**：不造成伤害、不附加任何效果，日志显示「攻击落空」 |
| `skipDefensiveChance` | 0.6 | 每条龙行动时 **60% 概率完全不考虑防御类技能**（护盾 / 治疗 / 免疫 / 净化 / 生命上限），只能从输出和削弱技能里选 |

落空只针对「打向敌方的技能」，敌方给自己人加 buff 不会落空。

### 平衡现状（AI 对 AI）

`node tools/sim.js 120` → 我方胜率 **92%**，平均 4.6 回合，场均伤害 我方 888 亿 / 敌方 479 亿。

两件事值得注意：

1. 对局变短了：火焰和光明都是「主目标 100% + 其余 85%」的全额 AOE，一次技能等于 2.7 次单体攻击，
   一回合就能打掉对面半队血，所以平均只有 4 回合
2. 敌方偏弱：黑暗系在最新表里只剩封印（不带伤害），城市守护龙因此**没有任何输出牌**，
   叠加 20% 落空 + 60% 不出防御牌两条规则，敌方输出明显不足

如果还想再紧一点，`src/engine/battle.js` 顶部有开关（默认不影响数值表）：

```js
const BALANCE = { enemyOutgoing: 1 };   // 敌方伤害倍率，调到 1.2 会更难
```

> 所有尺寸都是 **840×420 设计稿里的像素值**，再由整体 scale 放大缩小，所以改数字时按设计稿量即可。

## 调试参数

- `index.html?speed=3` 3 倍速（可叠 `?auto=1&speed=3`）

## 数值验证

```powershell
node tools/sim.js 100      # 无头跑 100 场
```

当前配置（AI 对 AI）参考结果：我方胜率约 52%、平均 8 回合、最长 17 回合（第 13 回合起进入白热化，伤害逐回合 +10%，不会无限互相加血）。
两边都有克制关系时伤害浮动很大，所以胜负比较看属性搭配。
